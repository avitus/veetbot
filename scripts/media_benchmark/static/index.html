    How each number is measured
    Clock
    Every time is in seconds from the click that started the run, taken from the browser's monotonic clock. Both requests leave in the same tick.
    First frame
    The first frame the page actually displays that is not blank. The same detector watches both videos, so a black hold or an empty stream does not count.
    Generation
    Reactor: from the enqueue command to the model's clip_generated message. TensorScale: from the request to the response headers, because the buffered endpoint answers only once the video exists. For the streaming LTX endpoint it runs to the last byte.
    Setup
    Reactor only: minting the session token, connecting the WebRTC session, and choosing the canvas. A warm run reuses an open session, so this is near zero.
    Delivery
    From generation done to the first frame on screen. For Reactor this is playout start plus the network. For TensorScale it is the download plus the decode.
    Finished
    When the last frame has been shown. Reactor streams in real time, so this includes the clip's own length. TensorScale's file starts as soon as it has downloaded.
    Generation speed
    Seconds of video per second of generation. Above 1× is faster than real time.
    Network and frames
    Reactor's round-trip time, jitter, packet loss, freezes and received bytes come from its WebRTC statistics during the clip. Dropped frames come from the video element for both providers.
    Cost
    TensorScale uses its published per-second price for the chosen model and resolution, checked 2026-10-09. Reactor uses the rate you enter.
